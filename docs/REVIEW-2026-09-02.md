# nrw-events review — implementation brief

Date: 2026-09-02. Baseline: `main` @ f0f415d, Python 3.14.7, 1376 tests green in 11 s,
88 % coverage, ruff (E9/F) has 1 error, mypy scoped to `core.py` has 7 errors.

Audience: a coding agent implementing fixes. Every item below was reproduced against the
real functions (`PYTHONPATH=scripts python3 …`) or by reading the exact code path. Items
marked **[repro]** include the input that demonstrates the bug; turn that input into the
regression test.

## Ground rules for the implementer

1. Stdlib only. No new runtime dependencies (`pyproject.toml` `dependencies = []`).
2. One PR per numbered item (or per explicitly grouped items). Small diffs, root-cause
   fixes in the shared function, never per-caller patches.
3. Each fix ships with one regression test that fails before and passes after. Use the
   existing `tests/helpers.py` context and `tests/sources/parser_cases.py` patterns.
4. After every change: `bash scripts/test.sh`, `.venv/bin/ruff check scripts tests`,
   `python3 scripts/generate_docs.py --check` (README/SKILL inventories are generated),
   `python3 scripts/check_env_docs.py`.
5. Do not change `identity.py` hashing inputs without updating
   `tests/data/event_id_vectors.json` and noting the website TypeScript twin (README).
6. Preserve the "no fabricated data" rule: fixes must reject or leave blank, never guess.

## Tier 1 — fix first (data loss, wrong data, or silent failure)

### R1. Typed adapters with a transport error are reported `healthy_empty`
- **Where:** `scripts/nrw_events/runner.py:220-236` (`_run_source`), `health.py:247-259`.
- **Problem:** `SourceResult.finish()` correctly sets `DEGRADED` when any endpoint has
  `error_type`. The runner then overwrites it: when the adapter returned a typed
  `SourceFetchResult` with status `HEALTHY_EMPTY` and no `parser_empty` flag, the typed
  status wins. Only `result.warnings` is re-checked, not endpoints. Every registry source
  is wrapped by `typed_adapter_for`, so this is the common path.
- **[repro]** Adapter calls `core._record_endpoint(url, error_type="URLError", error="boom")`
  and returns `SourceFetchResult.success([])` → `healthy_empty`. Same adapter returning a
  bare `[]` → `degraded`.
- **Impact:** retention (`_retention_labels`) does not protect the source, prior events
  drop from the snapshot, run status stays `healthy`, exit 0.
- **Fix:**
  ```python
  endpoint_errors = any("error_type" in e for e in result.endpoints.values())
  if typed_status in {DISABLED, SCHEDULED_SKIP, PARSER_EMPTY, DEGRADED}:
      result.status = typed_status
  elif typed_status == HEALTHY_EMPTY and not explicit_parser_empty and not endpoint_errors:
      result.status = typed_status
  ```
- **Test:** `tests/test_runner_output.py`: typed empty result + recorded endpoint error →
  `degraded`, source appears in `retained_sources`.

### R2. Truncated HTTP bodies are accepted as success
- **Where:** `core.py:279-309` (`_read_response_body`).
- **Problem:** `HTTPResponse.read1()` returns `b""` on premature EOF when `Content-Length`
  is set; it does not raise `IncompleteRead`. A half-delivered listing parses as a healthy
  run with fewer events.
- **[repro]** Local `http.server` sends `Content-Length: 1000`, writes 400 bytes, closes.
  `fetch_url` returns 400 bytes, endpoint recorded as 200.
- **Fix:** after the read loop:
  ```python
  if getattr(response, "length", None):  # bytes still owed per Content-Length
      raise ConnectionError(f"response truncated, {response.length} bytes missing")
  ```
  `ConnectionError` is already in the retryable set.
- **Test:** `tests/test_http_headers.py` with a stub response exposing `.length`.

### R3. `clean_html` unescapes before stripping tags and deletes real prose
- **Where:** `core.py:1181-1184`, `1212-1219`.
- **[repro]** `clean_html("Kinder < 6 Jahre > frei")` → `"Kinder frei"`;
  `clean_html("Alter &lt; 12 Jahre, Preis &gt; 5 €")` → `"Alter 5 €"`.
- **Impact:** titles, descriptions, admission inference lose age limits and price text.
- **Fix:** strip comments/script/style/tags on the raw markup first, then `unescape()`.
  `richtext.from_plain_text` re-escapes on render, so output stays safe.
- **Test:** the two inputs above.

### R4. One list-valued JSON-LD field kills every event on the page
- **Where:** `core.py:2524-2530` (`events_from_jsonld`), `dates.py:67`.
- **[repro]** Page with two Events, first has `"startDate": ["2026-09-10T19:00:00+02:00"]`
  → `AttributeError: 'list' object has no attribute 'replace'`, zero events, source fails.
  Lists for `name`, `image`, `startDate` are common in Yoast/WordPress output.
- **Fix:** coerce at the boundary:
  ```python
  def _jsonld_text(value):
      if isinstance(value, list):
          value = next((v for v in value if isinstance(v, str)), "")
      return value if isinstance(value, str) else ""
  ```
  Apply to `name`, `startDate`, `endDate`, `description`, `url`. Wrap each item in
  `try/except (TypeError, AttributeError, ValueError)` → skip item, record a warning.
- **Test:** the two-event page above yields 1 or 2 events, never 0.

### R5. `rc.dedupe` collapses distinct same-day showtimes
- **Where:** `sources/regional_common.py:333-341`; 36 adapters end with `rc.dedupe(events)`.
- **[repro]** Two records identical except `time` `18:00` / `21:00` → `rc.dedupe` → 1,

- **Impact:** second screening/performance vanishes every run for cinemas and multi-show
  venues (`cinema_specials.py:118`, `bonn_venues.py:54`, `requested_venues.py:41`, …).
- **Fix:** make `dedupe` delegate to `dedupe_occurrences`; delete the old body.
- **Test:** `tests/test_regional_common.py` with the pair above.

### R6. Yearless numeric German dates never parse; ranges drop the start day
- **Where:** `dates.py:141-192` (`parse_date`), `regional_common.py:368-379` (`range_dates`).
- **[repro]** `parse_date("12.03.")` → `None`; `rc.range_dates("12. – 14.03.2026")` →
  `(14.03, 14.03)`. `event_in_window` treats `None` as "unknown → include".
- **Impact:** multi-day festivals published on their last day only; five adapters carry
  private yearless resolvers (`regional_venues.py:314`, `bonn_districts.py:352-370`,
  `theater_marabu.py:44`, `requested_venues.py:392`, `cinema_specials.py:306`).
- **Fix:** in `parse_date`, after the `dd.mm.yyyy` branch:
  ```python
  m = re.match(r"^(\d{1,2})\.(\d{1,2})\.?(?!\d)", text)
  if m:
      ref = reference_date or _REFERENCE_DATE or datetime.now(LOCAL_TIMEZONE)
      return _next_yearless_occurrence(int(m.group(1)), int(m.group(2)), ref)
  ```
  In `range_dates`, take start via `parse_date(text)` (its `_range_start` inherits
  month/year) and end from the last full date; delete the first regex. Then delete the
  five local resolvers.
- **Test:** the two inputs above plus `"12.–14.09."`.

### R7. Any `*führung` title is forced to `outdoor` with confidence 1.0

- **Test:** `tests/test_category_taxonomy.py` with the three titles → stage/cinema, and

### R8. Same-source events at different venues are merged

### R9. `event_id` moves when a description is enriched
- **Where:** `normalization.py:416-420` (`canonical_venue_id` folds `description` into the
  matched text); `identity._venue_key` prefers `venue_id`.
- **[repro]** `{"title":"Antikmarkt","venue":"Bad Godesberg","city":"Bonn","description":""}`

  `rigalsche-wiese-bad-godesberg` → different `event_id`. Violates the README stability

### R10. `normalize_title` prefix strip is not word-anchored
- **Where:** `report.py:199`.
- **[repro]** `normalize_title("Konzertabend mit Anna")` == `normalize_title("Abend mit
  Anna")` == `abendmitanna` → `events_are_duplicates` True. Also
  `Ausstellungseröffnung: Farbe` → `seroeffnungfarbe`.

### R11. Junk-title terms match as substrings and drop real events
- **Where:** `junk_rules.py:112` (`_first` uses `term in text`), `junk_rules_data.json`
  `junk_title` (`contact`, `kontakt`, `jobs`, `faq`, `impressum`, …).
- **[repro]** `Contact Improvisation Jam` → `metadata.navigation-page` (`contact`);
  `Steve Jobs – Vortrag über Apple-Design` → same (`jobs`).
- **Fix:** match `junk_title` terms with `\b…\b` (or `fullmatch` on the whole title);
  these describe entire nav pages. Same treatment for governance terms (`:187`): check
  title+category only, word-bounded (`Sitzungssaal` venue currently drops talks).
- **Test:** `tests/test_junk_filter.py` with both titles kept; `Kontakt` alone dropped.

### R12. AI enrichment: batch-deadline tail poisons the negative cache for 24 h
- **Where:** `ai_enrichment.py:2194-2205` (`enrich_one`), `_record_failure`,
  `_TRANSIENT_FAILURE_CACHE_HOURS = 24` (`:63`).
- **Problem:** with `remaining` seconds left the per-call timeout becomes
  `remaining / (2*max_attempts)`; at 2 s that is 0.5 s. A facts call with a 5 000-token
  budget cannot finish → `TimeoutError` → transient error → immediate retry with the same
  tiny budget → terminal → `negative_until = now + 24h`. The last ~`workers` events of
  every run are skipped for a day and reported as `skipped=False`.
- **Fix:** in `enrich_one`, if `remaining / maximum_calls_per_event < 20` return the
  cached fallback with `skipped=True`. In `enrich_event`, do not call
  `_record_failure(terminal=True)` for a `TimeoutError` when the effective timeout was
  reduced below `configured.timeout_seconds`.
- **Test:** `tests/test_ai_enrichment.py`: near-deadline event → skipped, no negative row.

### R13. AI enrichment: no backoff on 429/5xx, then 24 h negative cache
- **Where:** `ai_enrichment.py:1957-1980`, `2046-2090`. `Retry-After` is discarded by
  `_read_response_isolated`.
- **Fix:** on `transient` errors `time.sleep(min(base * 2**attempt, remaining))` before
  retry; reuse `core._retry_delay`. Do not mark a 429 terminal until attempts are
  exhausted after a backoff. Forward `Retry-After`.
- **Test:** fake API returning 429 then 200 → success, one sleep observed.

### R14. Exa search: article publish date becomes the event date
- **Where:** `sources/search.py:60`, `core.py:3055-3066`, `core.py:1494`.
- **Problem:** description passed to `search_result_event` is
  `f"{publishedDate} {text}"`; `extract_dates` matches ISO first, so the publish
  timestamp becomes `start`/`end`. Any page published this week naming a local town
  becomes an "event" today.
- **Fix:** extract dates from `text` only; use `publishedDate` solely to reject stale
  pages.
- **Test:** `tests/sources/test_search.py`: result with `publishedDate` today and
  text date next month → event on next month's date.

### R15. Total outage exits 0 and republishes stale data; metadata points at the mutable file
- **Where:** `runner.py:332-345` (`_run_status`, `EXIT_DEGRADED = 0`), `:697-701`
  (`consecutive_failures` written, never read), `:2135` (`"events_path":
  settings.json_out`), `_previous_snapshot` (`:453-470`).
- **Problem:** with every source `FAILED`, retention keeps all prior events, status is
  `degraded`, exit 0, a fresh generation with a new `generated_at` is committed. Nothing
  consumes `consecutive_failures`. Separately, `events_path` names the fixed file, so
  after a degraded run the next run pairs `source_results` from run N-2 with events from
  run N-1 (see `run_canary.sh`, which only copies meta on clean runs); a crash between
  the two `_atomic_json` calls at `:1179-1180` leaves a mismatched pair.
- **Fix:** (a) in `_run_status`: `if not any(r.event_source_ids for r in
  results.values()): return "failed"`. (b) In `_publish_snapshots`, before the first
  dump: `metadata["events_path"] = str(immutable_events)`. (c) Either consume
  `consecutive_failures` (fail after N) or delete it.
- **Test:** all sources failed → exit 2, no new generation.

## What is solid (do not "fix")

- Failure isolation: `_run_source` catches everything; per-source wall-clock budget is
  enforced from both sides (runner deadline loop + `cancel_event`/`hard_deadline` checked
  inside body reads and retry sleeps); stuck daemon workers are replaced and cannot block
  exit. Verified live with a hung fetcher.
- Publication is a real transaction: `flock`, immutable per-run generation, fixed outputs,
  manifest as commit record; `run_status == failed` keeps last-known-good.
- HTTP: chunked reads with per-chunk socket timeout, 10 MB cap, retry only on transient
  statuses, POST retry opt-in, `Retry-After` honored, `HTTPError` closed on all paths.
- Detail cache: atomic `os.replace`, version + namespace check, dirty flag, TTL pruning.
- `richtext`: construct-not-filter, no attribute passthrough, escapes data on render.
- AI enrichment: each request in a killable subprocess with a hard wall-clock and 5 MB
  bound; daily cache-miss budget under `BEGIN IMMEDIATE`; facts sanitizer requires
  source support for city/venue/admission; `strip_restricted_copy` on every failure path.
- Identity: small documented tuple, end time deliberately excluded, order-independent
  collision suffixes, golden vectors run in `tests/test_event_identity.py:196`.
- Dedup: blocking index with frequency cap, transitive closure pass, merged winners
  re-canonicalized; house-number guard is a cheap, smart anti-merge signal.
- Tests: network hard-blocked in `tests/__init__.py`; no skips; 1376 tests in 11 s.
