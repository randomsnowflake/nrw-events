# Architecture

`nrw-events` is a standard-library event importer with a declarative source
registry and dedicated adapters for proprietary pages. It publishes one
validated snapshot plus metadata, highlights, and a recurring-series ledger.

## Runtime flow

```text
CLI / runner
  -> validated SourceSpec registry
  -> declarative adapters or sources/*.py
  -> RawEvent dictionaries
  -> validation and canonical event contracts
  -> deduplication, ranking, series, and highlights
  -> atomic snapshot publication
```

`runner.py` owns configuration, source fan-out, health accounting, boundary
validation, snapshot assembly, and atomic publication. A source failure is data
in the run result; one adapter must not terminate unrelated adapters.

## Layers and dependency direction

1. **Contracts and runtime state** — `models.py`, `runtime.py`, `health.py`,
   `source_types.py`, and `config.py` define typed values and validated settings.
2. **Domain policy** — `category_taxonomy.py`, `dates.py`, `identity.py`,
   `location.py`, `normalization.py`, `quality.py`, `richtext.py`, `scoring.py`,
   `series.py`, `title_normalization.py`, and `validation.py` implement reusable
   decisions without source-specific event data.
3. **Shared ingestion implementation** — `core.py` contains the historical
   implementation for HTTP, parsing, event construction, and compatibility
   runtime state. It is intentionally visible in the architecture: at roughly
   3,200 lines it remains the largest migration boundary, not a small helper.
   The focused `http.py`, `text.py`, `event_builder.py`, `ical.py`, and
   `jsonld.py` modules are currently compatibility re-export shims; migration
   has not yet separated their implementations from `core.py`.
4. **Compatibility facade** — `common.py` exposes legacy names and mutable window
   compatibility while adapters migrate to focused modules and `RunContext`.
   It must not acquire new source-specific policy.
5. **Sources** — `source_specs.py` loads `sources/registry.json`. Standard iCal,
   JSON-LD, and selector-based HTML integrations are declarative. Files under
   `sources/` exist for proprietary parsing or an explicitly grouped adapter and
   return raw event records; they do not publish files.
6. **Post-processing and output** — `report.py`, `highlights.py`, and `series.py`
   consume canonical records. Only `runner.py` coordinates durable publication.

Dependencies point from orchestration and sources toward contracts and shared
domain modules. Domain modules must not import individual sources. Source
adapters must not write snapshots or mutate another adapter's state.

## Source identity and health

Every registry row has a normalized stable `id`, display name, region, adapter,
and endpoint or callable contract. Aggregators with independently failing child
calendars also expose machine-readable child identities. Health is recorded per
endpoint and logical source before report-window filtering, so an empty parser,
scheduled skip, transport failure, and healthy zero-event result stay distinct.

## Generated documentation

The complete source and module inventories in `README.md` and `SKILL.md` are
generated by `python3 scripts/generate_docs.py`. The offline test suite runs the
same command with `--check`; changes to `registry.json` or package modules
therefore require a regeneration in the same commit. Editorial notes may
explain exceptional behavior, but they are not the canonical inventory.

## Change guidance

- Add a standard source as a `SourceSpec`; use a dedicated module only when the
  upstream format requires proprietary parsing.
- Keep network and parser telemetry in the shared ingestion path.
- Normalize and validate at the source-to-pipeline boundary; do not fabricate
  missing dates, admission, locations, or descriptions.
- Add regression fixtures for the exact upstream shape and run the full offline
  suite before publication.
